# A′ / D′ 原图诊断

用户提供的两张图来自 `F:\HuaweiMoveData\Users\25779\Desktop\抽卡\2.1`，本目录保留副本：[A′](candidate_A_prime.png)、[D′](candidate_D_prime.png)。它们仅是当前设计问题的证据，不是论文参考图，也不是本轮要继续编辑的底稿。

## A′：graph-centric

版本树占据上排，但视觉重量由下排三个有边框的功能区瓜分：训练、需求解析、隔离执行。`v4` 在上方出现一次，在下方分析又出现一次，`v7` 与执行完成后的结果也重复；读者得沿多条跨区箭头重新拼接身份。Git Agent 的小机器人符号是可读的，但缩小时几乎只剩轮廓，未成为全图稳定的角色标记。候选工作区边界和旧 `W4` 有区分，这是应保留的语义。改善需要**一条真正贯穿的 v4→v7 分枝，机制从这条枝的具体位置展开**，不是再减少边框数量。

## D′：transformation-centric

工作槽位的保留/更新/排除更直观；但大量相似矩形、短列表和箭头让每种科学对象失去不同形态。更严重的是两个原图可见的语义错误：反馈卡把 `Legacy API support` 标成 `+`，而用户给定实例是**排除旧 API**；“historical W4”画在虚线隔离候选区内，违反历史 checkpoint 不进入候选区、也不原地修改的定义。图上 `v7` 另置一处并用长弧回连，也削弱了 v4 分枝上的局部生成关系。后续草图必须把旧 `W4` 放在边界外，让副本 `W_t^0` 穿过边界。

## 共因与验收

两图的根本问题不是颜色或边框粗细，而是**主科学对象断裂**：版本图、控制策略、工作变换、训练各自成为一个区域，每段又画一次“流程”。新草图验收时先遮住小字：应仍能看到同一历史图上的 v4 分叉、旧状态到隔离候选的复制、以及训练回到**同一个** Git Agent。然后再读小字验证 `q_t`/`Q_t`、COMMIT 后 Router、REUSE 旁路、失败只丢弃候选。
