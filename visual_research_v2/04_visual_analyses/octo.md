# Octo — An Open-Source Generalist Robot Policy

**核验。** [RSS 2024 正式记录](https://www.roboticsproceedings.org/rss20/p090.html)；[原始 PDF](https://www.roboticsproceedings.org/rss20/p090.pdf)；[Fig. 1，PDF p1 原图](../03_figure_gallery/octo_fig1_pdfp1.png) / [680 px 预览](../03_figure_gallery/octo_fig1_680px.png)。图注把左侧定义为任务/观测，中央为可适配的 Octo 策略，右侧为动作空间，下方照片是实机与微调场景。

- **第一眼与全局：** 大号中央策略轮廓和 Octo 小形象先被看到；左边两组输入、右边动作、下方任务结果围绕同一中心对象。不是三行工作流。中央策略约占主示意宽度的半数，使科学对象有“主角”。
- **具体图形语言：** 拼图插口暗示输入与策略的适配关系；左边任务照片/语言人头像/相机与 proprioception 符号类别分明，右边机器人动作符号与照片对应真实输出。Octo 小章鱼具有角色辨识度，但体量小、与策略同位置；淡粉色连接带比箭头更像“兼容的接口”。同一描边、圆角、暖色辅助图形维持整体一致。图标承载输入/输出类型，章鱼仅辅助识别，绝不能把独特拼图边/章鱼搬进 GitHarness。
- **局部与证据：** 下排实物照片是上方方法能处理任务的实证例子，不是第二条方法链。细节以真实可视对象承载，文本多是名词短语；缩到 680 px 后照片与中心角色仍成立，任务小字变弱但不阻止读取主命题。
- **GitHarness 应用：** 可让“成对版本节点”成为稳定主对象，并用一致的紧凑 Git Agent 角色作为决策主体。历史图与候选构造若围绕 v4 节点展开，比独立大框有整体感。可以借“科学对象的一致轮廓与小插画”而不借拼图隐喻，因为 GitHarness 不是多模态适配；候选工作也不是任意可插拔模块。
