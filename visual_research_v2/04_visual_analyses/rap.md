# RAP — Reasoning with Language Model is Planning with World Model

**核验。** [EMNLP 2023 正式记录](https://aclanthology.org/2023.emnlp-main.507/)；[论文 PDF](https://aclanthology.org/2023.emnlp-main.507.pdf)；[Fig. 1，PDF p2 原图](../03_figure_gallery/rap_fig1_pdfp2.png) / [680 px 预览](../03_figure_gallery/rap_fig1_680px.png)。同页图注和第 3 节将语言模型同时用作 world model 与推理/规划器；右侧树不是软件调用图，而是候选动作及奖励/搜索过程。

- **第一眼与整体形状：** 左侧语言模型/世界模型的局部循环，右侧搜索树，图上方对照线性 Chain-of-Thought。横贯的虚线使“线性链 vs 规划树”成为全图第一命题。最大科学对象是右侧树，而非任意模块框。
- **图标与语法：** 同一小机器人头像出现于两处，稳定标记 Language Model 身份；地球云朵表示 world model，齿轮表示动作，星形表示 reward。这些都对应真实方法变量，黑白线条约同一线宽，只有少量状态/奖励色。树的圆节点表示状态，边是动作，红色回传箭头表示搜索评价；形状比文字先建立类别。
- **展开方式：** 左侧把一个状态-动作-预测-奖励步骤展开，右侧显示该步骤如何嵌进整棵树。两处用相同 `s_t, a_t, r_t` 而非重新解释对象，局部与全局在概念上共用状态。图虽有虚线分隔，两个部分不是无关模块。
- **密度与论文宽度：** 680 px 下树拓扑、机器人、世界模型仍可识别；小的状态下标需放大读。因此适合借“形态与拓扑先行”，不适合照搬每条边的标注密度。
- **GitHarness 应用：** Git Agent 可用一个较小且一致的角色符号；`V_i` 应像搜索状态节点有统一形态，`v4→v7` 真实分枝应承担因果语义。把 `W4→W_t^0→W̃_t` 作为从 v4 边上展开的局部转换。训练奖励可用星形/标记区分，但不能模仿搜索树回传：GitHarness 的 GRPO 更新的是策略参数，不是给历史节点改值。切勿把 world model 云朵或机器人外形描摹到最终图。
